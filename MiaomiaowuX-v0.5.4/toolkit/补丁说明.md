# 补丁包：MMWX v0.5.4 —— 一次性移除全部 VIP / PRO 特性检测

> 授权审计产物，仅用于自建沙箱实例。

## 1. 结论：VIP 检测是**单点汇聚**的

Garble 只重命名了标识符，**没有打散调用图**。脱壳后解析 Go pclntab
（注意：厂商把 pclntab magic 从 `0xfffffff1` 改成了 `0xd7c8c0ec`，属于轻度反分析），
即可拿到全部 102,731 个函数的精确地址。

许可包 `IWPMOgYs4`（garble 名）里有一个**总闸门**：

```
IWPMOgYs4.(*BcGS_j).HasFeature(key string) bool VA 0x17b4180
```

全二进制扫描 `call` 指令后统计它的调用方 —— **20 处调用点 / 18 个调用方**：

| 调用方 | 覆盖的 VIP 能力 |
|---|---|
| `(*BcGS_j).CanUsePremiumTheme` | 高级主题（`theme-premium`）/ 液态玻璃 / 自定义 CSS |
| `(*BcGS_j).HasFeatureForDataPlane` | 数据面：节点限速、连接数限制 |
| `JLKbOa2Pg.(*EEyIhK5EEDsK).Dispatch` / `DispatchFetch` | PRO REST 接口（节点测速、分享服务器…） |
| `JLKbOa2Pg.(*K9AsWddxB7xg).ServeHTTP` / `(*RPdCJGxcv).ServeHTTP` | PRO 页面/配置下发 |
| `JLKbOa2Pg.(*Zi0EBcAJ).GetConfig` | PRO 配置生成 |
| `(*BcGS_j).a0iRwxdbcs` / `uVzrS_vmX` | 派生特性判定 |
| `ztAMZ3Q` / `bMvUZb` / `fcolsj6` / `hz8RcgJ9Hm` / `rf0aF6qLoIZ` … | 内嵌 Xray、REALITY 域名池、分享服务器等 |

**所以只要把 `HasFeature` 的入口改成 `mov al,1; ret`，全部 VIP 检测一次归零。**

## 3. 最简分发版（6 行，无需脚本/编译）

`patches/oneliner.sh`（与 Python 版产物 sha256 完全一致 = `573a95ffbafe3a75cdd6b196aa738ed24cab3771af90668ec9b9d6d6c2cb0243`）：

```bash
curl -sL -o mmwx https://github.com/iluobei/miaomiaowuX/releases/download/v0.5.4/mmwx-linux-amd64
cp mmwx mmwx-cracked && upx -d mmwx-cracked >/dev/null
p(){ printf "$2" | dd of=mmwx-cracked bs=1 seek=$(( $1 )) conv=notrunc status=none; }
p 0x13b4180 '\xb0\x01\xc3' # ★ 全部 VIP 检测归零
p 0x13b44a0 '\xb0\x01\xc3' # 数据面
```

## 4. 验证结果（A/B，官方版 12889 vs 破解版 12890）

| 观测点 | 官方 v0.5.4 | 破解版 | 判定 |
|---|---|---|---|
| `GET /` 注入的 `var ps` | `'false'` | **`'true'`** | ✅ 高级主题门禁解除 |
| `GET /api/user/license/status` 的 `premium_theme` | `false` | **`true`** | ✅ API 层同步放开 |
| 浏览器 `<html class>`（cookie 选 premium 主题） | `font-oplusans3 light` | **`theme-premium font-oplusans3 light`** | ✅ 高级主题真正生效 |
| `HasFeature` 机器码 | 736 字节完整实现 | `mov al,1; ret` | ✅ |

**配额（用户/服务器/节点数量）本次未测通 —— 如实记录：**

- 官方版与破解版在"新建用户"时**都**被服务端拦回同一条错误：
 `已达到用户数量上限 (3/3)，请升级许可证`
- 把前端 UI 的 `usage.max` 改大（解除浏览器侧拦截）后重测，**破解版仍然被拦**。
- 原因：该配额走的是**另一条独立路径** ——
 `VLgBxN.(*CjOdSUIBHq4).CreateUser`（地址 `0xd43000`，8896 字节）读取的是
 计划里的 `plan.max_users` / `LicenseUsage` 快照，**不经过** `(*BcGS_j).EffectiveUserQuota`。
 因此 §2 表里 3 条配额补丁对该路径无效（保留在脚本中无害，但不算有效补丁）。
- 下一步定位思路（已铺好路）：
 1. `(*xGRYHwaSuI).ServeHTTP`（带 `SetLicenseManager` 的 admin users handler）
 调用链为 `… → bcrypt.GenerateFromPassword → VLgBxN.(*CjOdSUIBHq4).CreateUser → GetOrCreateUserToken`；
 2. 配额判定在 `CreateUser` 内部或其 `funcN` 闭包中，经**接口间接调用**取得计划限额；
 3. 打断点/内存断点（gdb `hbreak` 到 `CreateUser` 返回路径）或直接 patch
 `LicenseUsage` 返回值即可覆盖。

## 5. 反检测提示（分发时注意）

1. **指纹变化**：官方发行物 sha256 = `ecc1020a…5657`；脱壳后 = `c11d44d4…`；
 打过补丁后 = `573a95ff…`。主控在 `POST license.miaomiaowux.com/api/v1/activate`
 的请求体里带 `build_fingerprint` 与 `client_fp.exe_sha256`，**服务端可识别改包**。
2. **Action Guard 默认关闭**（`MMWX_ACTION_GUARD=required` 才启用）。
 一旦厂商改成默认强制，`mmwx-guardd-master --verify-manifest-for` 会用
 签名 manifest 里的 `executable_sha256` 校验主控，本补丁立即失效。
3. 补丁产物是**脱壳后 132 MB** 的 ELF（比官方 36 MB 大），可自行 `upx` 再压回去，
 但重压缩后的头与官方 UPX 版本可能不同，同样会被指纹识别。
