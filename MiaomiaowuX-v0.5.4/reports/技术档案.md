| 2 | `upx -d` (4.2.4) | 36,605,840 B → **132,604,030 B** 原始 Go ELF |

## 7. 防御建议（按根因排序）

1. **打破单点汇聚**：不要把 5 项 PRO 能力 + 主题 + 数据面全部挂在同一个 `HasFeature()` 上。
   每项能力应有独立的服务端权威判定，且判定点分散在不同的调用链上。
2. **消灭 fail-open**：前端 `Gy()` 在当前实现中"签名校验失败 → 信任未签名 `plan.features`"。
   改为：校验失败即视为**无任何特性**，并上报异常；服务端不下发未校验的 plan。
3. **服务端权威化**：VIP 判定结果与配额判定不要下发前端让前端裁决；
   前端只做展示，所有放行决定由服务端独立完成。
4. **许可状态加完整性保护**：`system_settings.license_status` 用 AEAD + MAC 封装（密钥派生自
   machine-id + 内嵌盐），篡改即判定 invalid，而不是"仅忽略 valid 字段"。
5. **补齐反篡改**：UPX 在 `upx -d` 前零成本，应改为控制流混淆（Garble `--literals --tiny` / OLLVM）
   + 完整性自校验；把 Action Guard 从 opt-in（`MMWX_ACTION_GUARD=required`）改为**默认强制**。
6. **启用指纹拒绝**：主控已在 `activate` 请求中上报 `build_fingerprint` / `exe_sha256`
   （本次实测：官方 `ecc1020a…` / 脱壳 `c11d44d4…` / 打补丁 `1c1a5597…`），
   服务端应将其与官方签名 manifest 比对，不一致即拒绝授权。
7. **废弃静态 API Token**：`system_settings.api_token` 改为可轮换、带作用域与过期时间的凭证。
8. **pclntab magic 不是安全措施**：篡改 magic 只增加几行解析代码的成本，不应计入防护设计。
