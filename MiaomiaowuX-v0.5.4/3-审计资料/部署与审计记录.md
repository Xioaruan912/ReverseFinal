## 2. 部署结果（WSL Debian）

### 2.1 官方部署方式（仓库提供）

```bash
curl -sL https://raw.githubusercontent.com/iluobei/miaomiaowuX/main/install.sh | sudo bash
# 无人值守：
MMWX_INSTALL_METHOD=native MMWX_DATABASE_DRIVER=sqlite sudo -E bash install.sh
# 或 Docker
docker compose up -d           # ghcr.io/iluobei/miaomiaowux:latest
```

仓库本体只有 14 个文件（安装脚本 + 规则模板 + compose），**真正的软件是 GitHub Release 里的
UPX 加壳 Go 单文件二进制 `mmwx`**。

### 2.2 本次实际使用的直启方式（便于动态分析，不依赖 systemd）

```bash
mkdir -p ~/mmwx/run && cd ~/mmwx/run
curl -sL -o mmwx https://github.com/iluobei/miaomiaowuX/releases/download/v0.5.4/mmwx-linux-amd64
chmod +x mmwx
PORT=12889 MMWX_LISTEN_PORT=12889 MMWX_DATA_DIR=$PWD/data nohup ./mmwx > mmwx.log 2>&1 &
```

启动后访问 `http://127.0.0.1:12889/`，首次进入为初始化向导：

1. 创建管理员账号（第一个注册用户自动成为 admin）→ 本次使用 `admin / Admin@12345`
2. 创建完成后跳转 `/login` 登录
3. 系统设置 → **License** 页签可查看许可状态、填写 License Key

数据目录（SQLite 模式）内容：

## 3. 逆向路径（证据链）

| 步骤 | 方法 | 结果 |
|---|---|---|
| 1 | `seep_r2_info` / 自写 ELF 解析 | ELF64, static, stripped, **熵 = 8.0000 bit/byte**，`shnum=0`，`entry=0xc5b8dc0` |
| 2 | 特征扫描 | 偏移 `0xEC` 发现 `UPX!` 魔数 → **UPX 加壳** |
| 3 | `upx -d`（upx 4.2.4） | 36.6 MB → **132.6 MB** 原始 Go 二进制，字符串全部可见 |
| 4 | 符号恢复 | Go pclntab 完整保留，garble 重命名的包名/函数名可直接读取 |
| 5 | 静态字符串 | Go 侧字面量被 **garble `-literals`** 加密，静态扫不到 `/api/v1/activate` 等 |
| 6 | **运行时内存取证** | `cat /proc/<pid>/mem` 转储 227 MB 堆 → 还原真实路由表、协议字面量、内嵌公钥 |
| 7 | 前端分析 | 主控内嵌 SPA（`/assets/index-*.js`, 713 KB），顺手 `js-beautify` 还原 |

## 4. 许可体系（还原后的真实架构）

### 4.1 三级签名信任链（**仅在前端实现**）

```
                 硬编码根公钥 h0 (base64 in index-*.js)
                        │  "mmwx-signing-key-cert-v1\n"+key_id
                        ▼
        signing_key_certificate = key_id.payload.sig   {version:1, issuer, key_id,
                                                        issued_at, expires_at, public_key}
                        │  "mmwx-entitlement-v2\n"+payload_b64
                        ▼
        entitlement = [key_id.]payload.sig             {version:2, issuer:"license.miaomiaowux.com",
                                                        audience:"mmwx-master",
                                                        master_public_key, features:[...]}
                        │  "mmwx-entitlement-session-v1\n"+sessionId+"\n"+sha256hex(entitlement)
                        ▼
        entitlement_session_sig                         (会话绑定，防重放)
```

- 根公钥：`1mOqVQuZPyeioJVLzG66z+Xdh3AdpdL0JsTmZ2nlEEA=`（32 B，Ed25519）
- 时钟容差 `Hu = 300 s`
- 校验函数：`b0()`（证书链）/ `y0()`（entitlement + 会话绑定）/ `Gy()`（特性判定）

### 4.2 服务端（主控）侧

- `license_status` **明文 JSON** 缓存在 `system_settings` 表
- 主控向 `https://license.miaomiaowux.com/api/v1/activate` 与 `/api/v1/heartbeat` 上报，
  请求带 Ed25519 签名（域分隔 `mmwx-master-request-v1/v2`）与 `build_fingerprint`
- **响应签名用内嵌（pinned）公钥校验**，伪造许可服务器会被识破
- 内嵌 3 个 32 B 公钥常量（弦内字符串取证）：
  `1mOqVQuZPyeioJVLzG66z+Xdh3AdpdL0JsTmZ2nlEEA=` / `AjWSOIeI3DejZAlVv3xCs9wsYsqiFIZlI3hig6XTaP4=` / `GJIsOMITopsBmTByoukB1kyS7yMjRtSmkgyGWf41Dsg=`
- 配额（users/servers/nodes）由 `EffectiveUserQuota` / `EffectiveServerQuota` / `EffectiveNodeQuota` /
  `QuotaEnforced` / `LicenseUsage` 等服务端函数执行

### 4.3 PRO 特性键（前端 `hi[]` 常量 + 后端枚举）

| key | 名称 | 判据位置 |
|---|---|---|
| `speed_test` | 节点测速 | 前端 UI + **后端 API 拒绝**（实测 `{"error":"节点测速是 PRO 功能，请升级许可证"}`） |

| `server_share` | 分享服务器 | 前端 UI |
| `embedded` | 内嵌 Xray | 前端 UI |

## 5. 已执行的验证实验

| # | 实验 | 结果 | 结论 |
|---|---|---|---|
| E1 | 伪造 License Key 提交 | `{"error":"invalid key"}` | 服务端向许可服务器校验，未通过 |
| E2 | 篡改 DB `license_status`（valid=true + PRO features） | 重启后主控重新判定为 `valid:false`，`plan` 被覆盖 | 单纯改缓存**不足以**提权；`entitlement` 字段被原样保留并回吐前端 |
| E3 | 离线模式（`/etc/hosts` 劫持 + `MMWX_OFFLINE=1`） | 主控进入 grace period，但仍按 invalid 处理 | 离线不放开许可 |
| E4 | **伪造许可服务器**（自建 CA 装入系统信任库 + `license.miaomiaowux.com:443` 假服务器） | 主控日志：`[license] response signature verification FAILED — ignoring response (possible forged license server / MITM)` | **防护有效**：响应签名 + pinned 公钥 |
| E5 | **前端 fail-open 验证（PoC）** | 仅注入未签名的 `plan.features`/`valid`/`premium_theme`，面板由 `Invalid / TRIAL` 变为 `Valid / PRO · 专业版` | **确认可绕过**：签名链失效时静默回退到未签名数据 |
